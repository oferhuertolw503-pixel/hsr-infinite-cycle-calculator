# V1 案例：四张截图的矩阵复算

本案例只采用 `docs/screenshots/` 下四张归档图片作为矩阵证据。节点简称：

- `H/H_U`：姬子行动/终结技；
- `T/T_U`：缇宝行动/终结技；
- `C/C_U/M`：截图写作“刻律”行动/终结技/军功，结合官方机制推断为
  刻律德菈；角色资料边界见 [v1_character_sources.md](v1_character_sources.md)。

## 一键验收

```bash
python -m src.v1
```

命令逐张检查图片文件、转录矩阵、谱半径和已报告特征向量。四项均显示
`PASS` 时，代表仓库已经如实复现截图；`PASS` 不等于证明实战永动。

## 四张图片与结论

| 图片 | 仓库数据 | V1 核验 |
|---|---|---|
| `case_4node_decay.png` | `four_node_model_N5.json`、`four_node_decay_real_family.json` | 显示矩阵 N=5 得 rho=0.88353，与图片一致 |
| `case_4node_kill.png` | `four_node_kill_real_family.json` | 显示矩阵 N=5 得 rho=1.02442，特征向量与图片一致 |
| `case_matrix_definition.png` | `seven_node_real_family.json` | 七节点逐格转录，保留 T→C_U=1/4 |
| `case_7node_matrix.png` | `seven_node_real_family.json`、`seven_node_table_calibrated_family.json` | 图片的矩阵与结果表存在一处内部不一致，两个版本分别保存 |

## 四节点：无击杀回能

按 `case_4node_decay.png`，节点顺序为 `H,H_U,T,T_U`：

```text
H    = [0,   1/4, 0,      1/4]
H_U  = [3/5, 3/5, 0,      0]
T    = [0,   0,   0,      1/2]
T_U  = [(4.5N+5)/97.5, 6N/97.5, 30/97.5, 5/97.5]
```

N=5 时计算 `rho=0.88353047`，截图显示 `0.88353`。因此纯线性模型衰减。

## 四节点：加入击杀回能

`case_4node_kill.png` 只把 `H_U` 行的两个 `3/5` 改成 `3/4`。复算得到：

| N | rho | 线性判定 |
|---:|---:|---|
| 2 | 0.98220 | 衰减 |
| 3 | 0.99683 | 衰减 |
| 4 | 1.01088 | 增长方向 |
| 5 | 1.02442 | 增长方向 |

截图只报告 N=5；N=2..4 是同一显示公式的计算结果。临界目标数是 N=4。

## 七节点：原图内部不一致

两张七节点图都显示 `T→C_U=1/4`。按显示矩阵复算：

| N | 显示矩阵 rho | 图片结果表 rho |
|---:|---:|---:|
| 2 | 1.00127 | 1.00522 |
| 3 | 1.01495 | 1.01872 |
| 4 | 1.02813 | 1.03174 |
| 5 | 1.04087 | 1.04432 |

仅把 `T→C_U` 从 `1/4` 改成 `1/2`，即可同时复现图片的四个特征值和
N=5 特征向量。因此仓库区分：

- `seven_node_real_family.json`：逐格转录，`T→C_U=1/4`；
- `seven_node_table_calibrated_family.json`：结果表校准，`T→C_U=1/2`。

校准版不是截图逐格原矩阵。后续如取得更清晰原始资料，应重新核对该单元格。

## V1 结论与下一步

V1 已完成“图片 → 矩阵 → 谱半径”的可复现链路。它能筛选线性衰减模型，
也能指出潜在增长方向，但 `rho>1` 仍不是实战永动的充分条件。

下一阶段寻找新永动机前，必须补齐：角色版本与配置、技能真实回能、资源上限、
触发阈值、敌方数量与刷新、行动时序和敌方行动。当前角色 JSON 只是演示骨架。
